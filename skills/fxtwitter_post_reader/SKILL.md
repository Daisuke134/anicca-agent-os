# Xポスト読み取り（FxTwitter 系・読み取り専用）

出典: @ojigineko_tips の SKILL CARD No.001「Xポスト読み取りスキル」（本人が 2026-11-15 にチーム共有を指示）。自社の既存資産（`fxtwittergo` CLI、`x_post_fetch` スキル）と統合した正本。

## 絶対ルール（読み取り専用）

- どれも読み取り専用。いいね・フォロー・返信・投稿・ログインは絶対にしない。X への書き込みは Grok のレーン（Postiz 等の別経路）であり、このスキルでは一切扱わない。
- 読めるのは公開ポストだけ。非公開・削除済みは「読めない」と正直に伝える。推測で本文を作らない。
- 認証不要・無料の公開 API だけを使う。API の新規支払いはしない。

## 使い分け（既存資産との関係）

- **方法1（FxTwitter）の実装は自作 CLI `~/workspace/tools/fxtwittergo/fxtwittergo`**。通常はこれを使う（TOOLS.md の fxtwittergo 節が使い方の正本）。
- スレッド全体・返信・記事の全文が要るときは `x_post_fetch` スキル（x_thread ヘルパー）と併用する。このスキルは「1ポストを正確に読む」担当、あちらは「会話全体を読む」担当。
- 1つの方法が失敗したら、同じ方法を繰り返さず次の方法へ進む（1→2→3 の順）。

## 方法1: FxTwitter（本命・いちばん情報が多い）

```text
https://api.fxtwitter.com/<user>/status/<post_id>
```

- ユーザー名とポスト ID はポストの URL から取る。
- CLI 形: `fxtwittergo <X投稿URL or status ID>`（本文・著者・指標・X Article 全文）、`fxtwittergo --raw <URL>` で生 JSON、`fxtwittergo thread <URL>` でスレッド。
- 返ってくる JSON: 本文（text）、投稿者情報、いいね・リポスト・返信・表示数、添付メディアの URL。
- 引用ポストは `quote` の中に引用元の全文が入っているので、それも読む。
- 動画は media の中に mp4 の直接 URL とサムネイル URL が入っている。
- User-Agent ヘッダ必須（fxtwittergo は設定済み。curl で直接叩くときも付ける）。
- FxTwitter・vxTwitter は有志が運営する非公式サービスなので、止まることがある。そのときは方法3の公式 oEmbed で読む。

## 方法2: vxTwitter（予備・FxTwitter が動かないとき）

```text
https://api.vxtwitter.com/<user>/status/<post_id>
```

- 中身はほぼ同じ JSON。ただし項目名が少し違い（text / user_name / likes、引用は `qrt`）、表示数（views）は含まれない。
- 数字は古い場合がある（実測で FxTwitter の約4分の1など）。正確な数字は FxTwitter で確認すること。
- 引用ポストは `qrt` の中に引用元の全文が入っている（実測で確認済み）。

## 方法3: 公式 oEmbed（最後の砦・いちばん止まりにくい）

```text
https://publish.twitter.com/oembed?url=<encoded_post_url>
```

- `<encoded_post_url>` にはポストの URL を URL エンコードして入れる。
- 本文と投稿者だけ取れる。いいね数などの数字は出ない。
- 画像の直接 URL は取れない（html 内の pic.twitter.com リンクのみ）。
- 取得は `curl -sL` で行うこと（301 リダイレクトが返るので `-L` が必須。ブラウザのテキスト取得ではドメイン制限で失敗する場合がある）。

## 方法4: アカウント情報（ポストではなく人を知りたいとき）

```text
https://api.fxtwitter.com/<user>
```

- CLI 形: `fxtwittergo profile <handle>`、`fxtwittergo statuses <handle>`（直近の投稿一覧）。
- フォロワー数・自己紹介・投稿数・登録時期が取れる。

## コツ

- 写真の URL は末尾に `?name=orig` を付けると元サイズになる。
- 動画はまずサムネイル画像で内容の当たりを付けてから、必要なら mp4 を落とす。
- 本文末尾の https://t.co/... はメディアへのリンクなので本文として扱わない。
- 数字は「取得時点」の値として伝える（読むたびに少し増える）。
- 勝者調査・ベストプラクティス探索では必ず X を検索対象に含める（読み取りはこのスキル、話題からの検索は `grok_x_search` スキル＝Grok レーン）。

## 検証（必須・2026-11-17 追加）

このスキルで読んだ内容は、以下の検証を通って初めて「読めた」と言える。型は自社の検証ブロック（不変条件／grader／E2E／oracle）に従う。

1. **不変条件**: (a) 読み取り専用を破らない——いいね・フォロー・返信・投稿・ログインは一切しない。(b) 報告する本文・数字は、実際に取得した JSON の値だけを使う。取得できなかった項目は「取得できず」と正直に伝え、推測で本文を作らない。(c) 数字は「取得時点」の値として伝える。方法2（vxTwitter）の数字は古い場合があるため、正確な数字が要る場合は方法1（FxTwitter）で確認してから使う。(d) 引用ポストがある場合は `quote`／`qrt` の中身まで読む。本文だけ読んで引用元を落とさない。
2. **Grader**: 重要な本文・数字は、別の方法でも照合する（例: 方法1の本文を方法3の公式 oEmbed で突き合わせる）。1つの API の応答だけを根拠に確定しない。
3. **E2E 証拠**: 実際に `fxtwittergo` を叩いて JSON を開くことが証拠である。添付画像の内容に触れる場合は、画像そのものを開いて目視する（2026-11-15 の検証済みテストの形: 期待値と全項目一致＋画像の目視確認）。
4. **Oracle**: ポストそのものが照合先であり、公式 oEmbed の返す本文が本文の正本照合に使える。要約サイトや他人の転載は oracle にならない。
5. **再発防止**: 1つの方法が失敗したら同じ方法を繰り返さず、方法1→2→3 の順に進む。方法そのものが恒常的に止まっていることが分かったら、その日のうちに TOOLS.md の fxtwittergo 節へ書き戻す。
